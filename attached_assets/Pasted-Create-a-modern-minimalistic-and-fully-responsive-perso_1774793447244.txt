Software Requirements Specification: Portfolio Chatbot 1. Core Response Strategy (How it should respond) Your portfolio chatbot should act as your virtual assistant. Domain Boundaries (The Guardrails): The bot must only answer questions related to your professional life. If asked about your skills: "I specialize in React, Node.js, and Python. If asked off-topic (e.g., politics, coding help, general trivia): "I'm specifically trained to answer questions about [Your Name]'s portfolio and experience. For general questions, you might want to try a standard search! Want to see their resume instead?" Fallback Mechanism: If the bot doesn't understand a query, it should gracefully fail and provide a direct call to action: "I'm not quite sure about that. The best way to get that answered is to email [Your Name] directly at [Your Email]." Prompting to Action: It should actively guide users to your resume, your contact page, or your featured projects. 2. Backend Architecture & Logic The backend serves as the brain, processing user input and returning the appropriate response securely. Logic Engine (Choose One): Option A: Rule-Based (Simple & Fast): Uses predefined keywords or RegEx to match user inputs to hardcoded responses. Great for simple portfolios. Option B: LLM Integration (Advanced): Uses an API like OpenAI (ChatGPT) or Anthropic. You pass a "System Prompt" containing all your resume data, instructing the AI to act as your assistant. API Design: Endpoint: POST /api/chat Payload: { "message": "What is your experience with React?" } Response: { "reply": "I have 3 years of experience..." } Security (Critical for Portfolios): Rate Limiting: Restrict requests (e.g., 10 messages per IP per minute) so malicious users don't drain your API credits or crash your server. Part 2: The Backend Folder Structure (FastAPI) To keep your code maintainable, you want to separate your routes (API endpoints), your logic (talking to the LLM), and your configuration. Here is the ideal directory structure for your chatbot backend: Plaintext portfolio-chatbot-backend/ │ ├── .env # Secret keys (OpenAI API key, CORS allowed origins) ├── requirements.txt # Python dependencies (fastapi, uvicorn, openai, pydantic) ├── main.py # The entry point of your application │ ├── api/ # API Routing │ └── chat_router.py # Contains the POST /api/chat endpoint │ ├── core/ # Configuration & Constants │ ├── config.py # Loads variables from .env │ └── prompt.py # Stores your long System Prompt (from Part 1) │ ├── models/ # Data validation (Pydantic schemas) │ └── schemas.py # Defines the shape of incoming requests and outgoing responses │ └── services/ # Business Logic └── llm_service.py # The function that actually sends the message to the AI API How the Flow Works in Practice: models/schemas.py: You define that a frontend request must look like {"message": "string"}. If a user tries to send {"image": "..."}, FastAPI blocks it automatically. api/chat_router.py: Receives the valid request from the frontend portfolio. services/llm_service.py: Takes the user's message, grabs the SYSTEM_PROMPT from core/prompt.py, bundles them together, and securely pings the LLM API. main.py: Configures your CORS settings so that only requests coming from https://your-portfolio-domain.com are allowed, preventing strangers from racking up your API bill from Postman or other sites.
